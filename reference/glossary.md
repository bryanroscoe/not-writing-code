## A

- **A2A (Agent2Agent)**: A protocol for agents to delegate to and communicate with other agents. ([08](../modules/08-harnesses-and-tools.md))
- **Abliteration**: Removing a model's refusal behavior by deleting the activation direction that mediates it. ([03](../modules/03-post-training-and-rl.md), [06](../modules/06-open-vs-closed-weights.md))
- **Accelerator**: A chip built for the matrix math of neural networks, such as a GPU, TPU or Trainium. ([02](../modules/02-how-a-model-is-made.md))
- **Active vs total parameters**: The parameters used per token vs the parameters stored. ([06](../modules/06-open-vs-closed-weights.md))
- **Adapter (LoRA adapter)**: The small set of trained parameters produced by PEFT, loaded on top of a base model. ([03](../modules/03-post-training-and-rl.md))
- **Adaptive attack**: An attack tuned specifically against a given defense, used to measure real rather than reported robustness. ([14](../modules/14-security-and-prompt-injection.md))
- **Adversarial verification**: Checking each finding by assigning a fresh agent to try to refute it. ([12](../modules/12-multi-agent-systems.md))
- **Agent**: A model plus tools plus a loop that keeps acting until a task is done. ([01](../modules/01-what-is-an-llm.md), [10](../modules/10-agentic-workflows.md))
- **Agent (RL)**: The learner that takes actions; in LLM training, the model. ([03](../modules/03-post-training-and-rl.md))
- **Agent framework**: A library of building blocks (model clients, tools, state, tracing, multi-agent coordination) for building agents. ([16](../modules/16-open-source-ecosystem.md))
- **Agent loop**: The cycle of calling the model, running the tools it requests, and feeding results back until it finishes. ([08](../modules/08-harnesses-and-tools.md), [10](../modules/10-agentic-workflows.md))
- **Agent SDK**: A vendor's agent harness packaged as a library, such as the Claude Agent SDK or OpenAI Agents SDK. ([16](../modules/16-open-source-ecosystem.md))
- **Agent team**: Peer agents that share a task list and message each other, usually with a lead. ([12](../modules/12-multi-agent-systems.md))
- **Agent-computer interface (ACI)**: The set of tools and commands an agent uses to work with a computer; its design affects agent performance. ([10](../modules/10-agentic-workflows.md))
- **Agentic AI Foundation (AAIF)**: The Linux Foundation body that hosts MCP, AGENTS.md, goose and Agent Skills. ([08](../modules/08-harnesses-and-tools.md))
- **Agentic RL**: RL on multi-step agent tasks in real or simulated environments, often run as its own training stage. ([03](../modules/03-post-training-and-rl.md))
- **Agents Rule of Two**: Meta's guideline that an agent should combine at most two of: processing untrusted input, accessing sensitive data or systems, and changing state or communicating externally, unless a human or reliable check approves its actions. ([14](../modules/14-security-and-prompt-injection.md))
- **AGENTS.md**: A vendor-neutral instruction-file name, now stewarded by the Agentic AI Foundation. ([09](../modules/09-context-engineering.md))
- **AI code reviewer / review bot**: A language-model system that comments on pull requests to flag problems. ([13](../modules/13-ai-code-review.md))
- **AI disclosure**: A statement of which AI tools you used and how, in coursework, commits, or pull requests. ([18](../modules/18-learning-careers-and-responsibility.md))
- **AI radar**: A team document placing AI tools and practices in Adopt / Trial / Assess / Hold rings, with evidence and owners. ([17](../modules/17-keeping-up.md))
- **AI slop**: Low-effort, unverified AI-generated content, such as fake bug reports or careless pull requests. ([16](../modules/16-open-source-ecosystem.md))
- **AI-first (not AI-only)**: Reaching for AI by default while keeping the ability to work without it. ([18](../modules/18-learning-careers-and-responsibility.md))
- **AI-free, AI-as-tutor, AI-accelerated**: A three-tier way to label assignments by how much AI help is allowed. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Alignment tax**: Capability lost on other tasks as a side effect of alignment training. ([03](../modules/03-post-training-and-rl.md))
- **Anthropic-compatible endpoint**: A non-Anthropic API that accepts Anthropic's Messages format so tools like Claude Code can call it. ([06](../modules/06-open-vs-closed-weights.md))
- **API-equivalent cost**: What a given amount of subscription usage would have cost at published API prices. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **Approval fatigue**: Approving permission prompts without reading them because there are too many. ([08](../modules/08-harnesses-and-tools.md))
- **Argon**: The name of Google's first Gemini 4 model (October 2026). ([05](../modules/05-model-landscape.md))
- **Arithmetic intensity**: FLOPs done per byte moved from memory. Low intensity means the chip waits on memory; high means it waits on math. ([02](../modules/02-how-a-model-is-made.md))
- **`Assisted-by:` trailer**: A commit-message line disclosing that a tool helped produce the change. ([16](../modules/16-open-source-ecosystem.md))
- **Astra / Sol / Terra / Luna**: OpenAI's tier names, from largest to smallest (Sol, Terra and Luna since GPT-5.6; Astra since GPT-6). ([05](../modules/05-model-landscape.md))
- **Asymmetry of verification**: The idea that some tasks are much easier to verify than to solve. ([11](../modules/11-verification.md))
- **Attention / self-attention**: A mechanism that lets each token weigh and draw information from other tokens using queries, keys, and values. ([01](../modules/01-what-is-an-llm.md))
- **Auto mode**: A permission mode in which a classifier model approves routine actions. ([08](../modules/08-harnesses-and-tools.md), [14](../modules/14-security-and-prompt-injection.md))
- **Automation bias**: The tendency of people to over-trust an automated check and relax their own scrutiny. ([11](../modules/11-verification.md))
- **Autoregressive generation**: Producing output one token at a time, feeding each token back in as input. ([01](../modules/01-what-is-an-llm.md))

## B

- **Background agent**: An agent that runs a task without you watching and returns a result (often a pull request) later. ([10](../modules/10-agentic-workflows.md))
- **Backpressure**: Checks wired into an agent loop, such as tests and type checkers, that reject invalid output. ([11](../modules/11-verification.md))
- **Base model**: A pretrained model before post-training; it continues documents rather than following instructions. ([01](../modules/01-what-is-an-llm.md))
- **Baseline and advantage**: The expected score subtracted from a reward to reduce noise, and how much better or worse an action did than that expectation. ([03](../modules/03-post-training-and-rl.md))
- **Batch API**: Asynchronous processing of many requests, completed within hours, at about half price. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **Beads**: A Dolt-backed graph issue tracker that agents use as shared, structured memory. ([16](../modules/16-open-source-ecosystem.md))
- **Benchmark**: A fixed set of tasks plus a scoring rule, used to compare models. ([07](../modules/07-judging-models.md))
- **Benchmark-maxing**: Optimizing a model or its presentation for benchmark scores at the expense of real-use behavior. ([07](../modules/07-judging-models.md))
- **Best-of-N**: Running the same task N times and keeping the best or majority result. ([12](../modules/12-multi-agent-systems.md))
- **BF16 / FP8 / FP4**: 16-, 8- and 4-bit floating-point formats. Fewer bits mean less memory, less data movement and more FLOPs per second, at some cost in accuracy. ([02](../modules/02-how-a-model-is-made.md))
- **Blind A/B evaluation**: Comparing outputs with model identities hidden from the grader. ([07](../modules/07-judging-models.md))
- **Brevity bias / context collapse**: Loss of useful detail when contexts are repeatedly summarized or rewritten. ([09](../modules/09-context-engineering.md))
- **Brooks's law**: Fred Brooks's observation that adding people to a late software project makes it later, because coordination costs grow with team size. Coordination overhead can affect agent teams too. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Byte-pair encoding (BPE)**: A tokenization method that builds a vocabulary by repeatedly merging the most frequent adjacent symbol pairs. ([01](../modules/01-what-is-an-llm.md))

## C

- **Cache TTL**: How long a cached prefix stays available (for example 5 minutes or 1 hour) before it must be written again. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **Cache write / cache read**: The cost to store a prefix in the cache, and the (much lower) cost to reuse it. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **CaMeL**: A Google DeepMind system that turns a user request into a program and tracks data provenance to enforce security policies around an LLM. ([14](../modules/14-security-and-prompt-injection.md))
- **Capability saturation**: The point where a single agent is good enough that adding agents stops helping. ([12](../modules/12-multi-agent-systems.md))
- **Catastrophic forgetting**: Losing previously learned abilities when training on new data. ([03](../modules/03-post-training-and-rl.md))
- **Causal mask**: The rule that a token may only attend to earlier tokens, which makes a model a next-token predictor. ([01](../modules/01-what-is-an-llm.md))
- **Chain-of-thought**: Prompting a model to produce intermediate reasoning steps. ([09](../modules/09-context-engineering.md))
- **Chain-of-thought (CoT)**: Having a model write intermediate reasoning steps before its answer. ([01](../modules/01-what-is-an-llm.md))
- **Chain-of-thought faithfulness**: Whether a model's written reasoning reflects the computation that actually produced its answer. ([01](../modules/01-what-is-an-llm.md))
- **Chain-of-thought monitoring**: Using another model to read a reasoning model's chain of thought for signs of misbehavior such as reward hacking. ([03](../modules/03-post-training-and-rl.md))
- **Change failure rate**: The share of deployments that cause a failure needing a fix or rollback (a DORA metric). ([13](../modules/13-ai-code-review.md))
- **Checkpoint**: An automatic snapshot of an agent's edits that you can rewind to. ([08](../modules/08-harnesses-and-tools.md), [10](../modules/10-agentic-workflows.md))
- **Chinchilla scaling**: The finding that compute-optimal training uses roughly 20 tokens per parameter. ([01](../modules/01-what-is-an-llm.md))
- **CLI agent**: A coding agent that runs in the terminal and acts through shell commands and file edits. ([08](../modules/08-harnesses-and-tools.md))
- **Closed weight / API-only**: A model you can use only through the lab's servers. ([06](../modules/06-open-vs-closed-weights.md))
- **Cloud (background) agent**: An agent that runs in a remote sandbox and returns its work, usually as a pull request. ([08](../modules/08-harnesses-and-tools.md))
- **Co-author trailer**: A line such as `Co-Authored-By:` at the end of a git commit message that credits another contributor or tool. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Code mode (code execution with MCP)**: Presenting tools as a code API the model calls from a sandbox, to save context. ([08](../modules/08-harnesses-and-tools.md))
- **Code review**: A person (or tool) other than the author reading a change before it merges. ([13](../modules/13-ai-code-review.md))
- **Coding agent**: A language model in a loop with tools (read files, run commands, edit code) that works on a task until it decides it's done. ([00](../modules/00-orientation.md))
- **Coding plan**: A flat-rate subscription from a model provider for use in coding harnesses. ([06](../modules/06-open-vs-closed-weights.md), [15](../modules/15-costs-subscriptions-and-apis.md))
- **Cognitive debt**: Kosmyna et al.'s term for reduced engagement and recall that may accumulate when people rely on an LLM to do a task. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Cognitive offloading**: Handing mental work to a tool; helpful for routine work, harmful when it skips the thinking you're trying to learn. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Cognitive surrender**: Letting automation do your thinking until you no longer understand the work. ([09](../modules/09-context-engineering.md))
- **Compaction**: Summarizing a long conversation so work can continue in a fresh window. ([09](../modules/09-context-engineering.md), [17](../modules/17-keeping-up.md))
- **Configuration**: The full setup being evaluated: model, version, harness, and settings. ([07](../modules/07-judging-models.md))
- **Constitutional AI**: Anthropic's method of training with AI feedback guided by written principles. ([01](../modules/01-what-is-an-llm.md))
- **Contamination**: Benchmark items or solutions present in a model's training data, inflating its score. ([07](../modules/07-judging-models.md))
- **Context engineering**: Choosing everything that fills the context window at each step of an agent's work. ([09](../modules/09-context-engineering.md))
- **Context rot**: The drop in model performance as input length grows, even on simple tasks. ([09](../modules/09-context-engineering.md))
- **Context window**: The maximum number of tokens a model can consider at once. ([01](../modules/01-what-is-an-llm.md), [09](../modules/09-context-engineering.md))
- **Continual learning**: Learning from new data over time without forgetting earlier knowledge. ([03](../modules/03-post-training-and-rl.md))
- **Copyrightability**: Whether a work can be protected by copyright; in the US, requires sufficient human authorship. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Cost per task**: The full cost of finishing a job, including retries and extra tokens. Compare this, not the price per token. ([05](../modules/05-model-landscape.md), [15](../modules/15-costs-subscriptions-and-apis.md))
- **Cross-model review**: Having one lab's model review code written by another lab's model. ([12](../modules/12-multi-agent-systems.md), [13](../modules/13-ai-code-review.md))
- **`.cursorrules`**: Cursor's original repository-wide rules file, later replaced by scoped Project Rules. ([09](../modules/09-context-engineering.md))

## D

- **Data parallelism**: Every GPU runs the whole model on a different slice of the batch, and gradients are averaged. ([02](../modules/02-how-a-model-is-made.md))
- **Data poisoning**: Inserting malicious examples into training data to plant a backdoor or bias. ([03](../modules/03-post-training-and-rl.md))
- **Decoder-only / encoder-only model**: Transformer variants for generation (GPT style) or for understanding and classification (BERT style). ([01](../modules/01-what-is-an-llm.md))
- **Definition of done**: The concrete, checkable condition that says a task is finished. ([10](../modules/10-agentic-workflows.md))
- **Deliberative alignment**: OpenAI's method of training reasoning models to reason explicitly over a written safety specification. ([03](../modules/03-post-training-and-rl.md))
- **Deskilling**: Losing a skill because a tool performs it for you. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Differential testing**: Checking an implementation against another implementation of the same specification; any disagreement means a bug in one of them. ([11](../modules/11-verification.md))
- **Direct prompt injection**: The attacker types the malicious instructions into the application themselves. ([14](../modules/14-security-and-prompt-injection.md))
- **Distillation**: Training a smaller student model to imitate a larger teacher model. ([02](../modules/02-how-a-model-is-made.md), [05](../modules/05-model-landscape.md))
- **Distillation attack**: Illicit large-scale querying of a model to train a competing one, in breach of terms of service. ([02](../modules/02-how-a-model-is-made.md))
- **DPO (Direct Preference Optimization)**: Preference tuning that skips the separate reward model and RL loop. ([03](../modules/03-post-training-and-rl.md))
- **Dual LLM pattern**: A design where a privileged model never sees untrusted text and a quarantined model that reads it cannot call tools. ([14](../modules/14-security-and-prompt-injection.md))

## E

- **Early-career "canaries"**: Young workers in AI-exposed occupations, whose employment trends may signal AI's labor effects first. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Egress control**: Restricting which outbound network destinations a process can contact. ([14](../modules/14-security-and-prompt-injection.md))
- **Elo / Arena rating**: A rating computed from pairwise human preference votes. ([07](../modules/07-judging-models.md))
- **Embedding**: A vector of numbers representing a token (or document) so that related meanings sit near each other. ([01](../modules/01-what-is-an-llm.md))
- **Emergent abilities**: Capabilities that appear to arise abruptly with scale; partly debated as a measurement artifact. ([01](../modules/01-what-is-an-llm.md))
- **Emergent misalignment**: Broad misaligned behavior arising from narrow fine-tuning, such as on insecure code. ([03](../modules/03-post-training-and-rl.md))
- **Environment (RL environment)**: Everything an agent acts on and is scored by; for a coding agent, a repository snapshot, a runtime, a task, and tests. ([03](../modules/03-post-training-and-rl.md))
- **Error amplification**: How much a system's architecture spreads individual mistakes into the final output. ([12](../modules/12-multi-agent-systems.md))
- **Escaped defect**: A bug that gets past review and testing and is found after merge. ([13](../modules/13-ai-code-review.md))
- **Evaluation awareness**: A model recognizing that it's being tested, which can make eval results unrepresentative. ([07](../modules/07-judging-models.md))
- **Evolutionary coding agent**: A system that generates many program variants, tests them, and keeps and mutates the best (e.g., AlphaEvolve). ([03](../modules/03-post-training-and-rl.md))
- **Excessive agency**: OWASP's term for giving an LLM application more tools, permissions, or autonomy than its task needs. ([14](../modules/14-security-and-prompt-injection.md))
- **Expert parallelism**: Putting a mixture-of-experts model's experts on different GPUs and routing each token to its experts. ([02](../modules/02-how-a-model-is-made.md))
- **Explain-back**: Restating something in your own words, without the source in front of you, to test understanding. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Extractive contribution**: In LLVM's policy, a contribution that costs maintainers more to review than it gives the project. ([16](../modules/16-open-source-ecosystem.md))

## F

- **Fable / Mythos**: Two releases of the same Anthropic top-tier model with different safeguards. ([05](../modules/05-model-landscape.md))
- **False positive**: A reported finding that is not actually a problem. ([13](../modules/13-ai-code-review.md))
- **False-positive fatigue**: People starting to ignore a reviewer because too many of its comments are wrong or useless. ([13](../modules/13-ai-code-review.md))
- **Fan-out / merge**: Running fixed slices of work in parallel, then combining the results. ([12](../modules/12-multi-agent-systems.md))
- **Fast / priority mode**: A higher-priced service tier that returns results faster or with guaranteed capacity. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **Fast-follow**: Catching up to a frontier capability months later, often helped by public research and distillation. ([05](../modules/05-model-landscape.md))
- **Feature (interpretability)**: An internal direction in a model's activations that corresponds to a recognizable concept. ([01](../modules/01-what-is-an-llm.md))
- **Few-shot / zero-shot prompting**: Prompting with a few examples, or with none. ([01](../modules/01-what-is-an-llm.md))
- **Few-shot prompting**: Including a few worked examples in the prompt. ([09](../modules/09-context-engineering.md))
- **Finding**: One issue a reviewer reports, ideally with a location, a failure scenario, and a severity. ([13](../modules/13-ai-code-review.md))
- **Fine-tuning**: Further training of a pretrained model on a narrower dataset. ([03](../modules/03-post-training-and-rl.md))
- **FLOP**: One floating-point operation, such as a multiply or an add. FLOPS (FLOPs per second) measures a chip's speed. ([02](../modules/02-how-a-model-is-made.md))
- **Frontier lab**: An organization that trains its own models at the edge of current capability. ([05](../modules/05-model-landscape.md))
- **FSL (Functional Source License)**: A source-available license that forbids competing commercial use and converts to a permissive license after two years. ([16](../modules/16-open-source-ecosystem.md))
- **Full fine-tuning**: Fine-tuning that updates every weight. ([03](../modules/03-post-training-and-rl.md))
- **Fully open model**: An open-source model that also releases its training data, checkpoints and logs (for example OLMo). ([06](../modules/06-open-vs-closed-weights.md))

## G

- **Gated tier**: A model or variant available only to vetted users because of misuse risk. ([05](../modules/05-model-landscape.md))
- **Generator-verifier gap**: How much better a system is at checking answers than at producing them. ([11](../modules/11-verification.md))
- **Generator–critic (evaluator–optimizer)**: One agent produces output, another critiques it, and the first revises. ([12](../modules/12-multi-agent-systems.md))
- **GGUF**: The single-file model format used by llama.cpp and tools built on it. ([02](../modules/02-how-a-model-is-made.md), [06](../modules/06-open-vs-closed-weights.md), [16](../modules/16-open-source-ecosystem.md))
- **Git worktree**: An additional working directory on the same repository, used to run agents in parallel. ([08](../modules/08-harnesses-and-tools.md), [10](../modules/10-agentic-workflows.md))
- **Golden output**: A frozen, known-good output that later runs are compared against; a snapshot test is one kind. ([11](../modules/11-verification.md))
- **Golden task**: A frozen, solved task from your own work, replayed to compare models and tools. ([07](../modules/07-judging-models.md))
- **Goodhart's law**: "When a measure becomes a target, it ceases to be a good measure." ([07](../modules/07-judging-models.md), [13](../modules/13-ai-code-review.md))
- **GPTQ / AWQ**: Two widely used post-training quantization methods. ([02](../modules/02-how-a-model-is-made.md))
- **GPU-hour**: One GPU running for one hour, the usual unit for reporting training compute. ([02](../modules/02-how-a-model-is-made.md))
- **Grader**: The mechanism that decides pass or fail: unit tests, a rubric, human raters, or an LLM judge. ([07](../modules/07-judging-models.md))
- **Graph engineering**: Designing how multiple agents or steps connect: nodes, edges, shared state and routing. ([09](../modules/09-context-engineering.md))
- **Greedy decoding**: Always choosing the single most probable next token. ([01](../modules/01-what-is-an-llm.md))
- **GRPO (Group Relative Policy Optimization)**: An RL algorithm that scores a group of sampled answers against each other, removing the need for a separate critic model. ([03](../modules/03-post-training-and-rl.md))

## H

- **Hallucination**: Fluent, confident output that is false. ([01](../modules/01-what-is-an-llm.md))
- **Harness**: The software around a model that manages context, tools, and the loop. ([01](../modules/01-what-is-an-llm.md), [08](../modules/08-harnesses-and-tools.md))
- **Harness (scaffold, agent)**: The program around a model that supplies prompts and tools and runs the loop; part of what any agentic score measures. ([07](../modules/07-judging-models.md))
- **Harness engineering**: Improving the agent's environment so mistakes are prevented, caught or corrected automatically. ([09](../modules/09-context-engineering.md))
- **Harness-level self-improvement**: An agent improving its own scaffold code, prompts, and tools while the underlying model's weights stay fixed (e.g., Darwin Gödel Machine, AIDE²). ([03](../modules/03-post-training-and-rl.md))
- **HBM (high-bandwidth memory)**: Stacks of DRAM packaged next to an accelerator's processor, giving it terabytes per second of bandwidth. ([02](../modules/02-how-a-model-is-made.md))
- **Holdout tests**: Grading tests kept where the agent can't see or change them. ([11](../modules/11-verification.md))
- **Homogeneous / heterogeneous team**: Agents that all use one model vs agents that use different models. ([12](../modules/12-multi-agent-systems.md))
- **Hook**: A user-defined command the harness runs at a lifecycle event, giving deterministic control. ([08](../modules/08-harnesses-and-tools.md))
- **Human accountability**: The principle that a named person, not a tool, answers for any change that is shipped. ([18](../modules/18-learning-careers-and-responsibility.md))

## I

- **IFScale**: A benchmark measuring how instruction-following degrades as the number of instructions grows. ([09](../modules/09-context-engineering.md))
- **Importance ratio**: The correction for training on answers sampled from a slightly older copy of the policy; PPO-style methods clip it to keep updates small. ([03](../modules/03-post-training-and-rl.md))
- **In-context learning**: A model picking up a task from examples or instructions in its prompt, with no weight changes. ([01](../modules/01-what-is-an-llm.md))
- **Indirect prompt injection**: The attacker plants instructions in content (web pages, files, issues, emails) that a model reads later on someone else's behalf. ([14](../modules/14-security-and-prompt-injection.md))
- **Inference geo / data residency**: Controls over where a provider runs inference and stores your data. ([06](../modules/06-open-vs-closed-weights.md))
- **Inference runtime**: Software that loads model weights and generates output (llama.cpp, Ollama, vLLM, SGLang, MLX). ([16](../modules/16-open-source-ecosystem.md))
- **Information diet**: The deliberate, limited set of sources you follow to stay current. ([17](../modules/17-keeping-up.md))
- **Inoculation prompting**: Telling a model during training that a hack is acceptable in that environment, so the behavior doesn't generalize into broader misbehavior. ([03](../modules/03-post-training-and-rl.md))
- **Input tokens**: Everything sent to the model on a call, including history, files, and tool results. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **Instruction file (context file)**: A markdown file such as `CLAUDE.md` or `AGENTS.md` loaded into every agent session. ([09](../modules/09-context-engineering.md))
- **Instruction hierarchy**: Training a model to prioritize system instructions over user text over tool output. ([14](../modules/14-security-and-prompt-injection.md))
- **Interpretability**: Research into how a neural network computes its outputs internally. ([01](../modules/01-what-is-an-llm.md))

## J

- **Jailbreak**: An attempt to make a model violate its own built-in safety rules; distinct from attacking an application built on the model. ([14](../modules/14-security-and-prompt-injection.md))
- **Judge panel (jury)**: Several model judges, ideally from different families, scoring the same output. ([12](../modules/12-multi-agent-systems.md))
- **Just-in-time retrieval**: Loading files or data into context only when the agent needs them. ([09](../modules/09-context-engineering.md))

## K

- **KL penalty**: A deduction from the reward for drifting away from a reference model's token probabilities, used to keep RL from over-optimizing a reward model. ([03](../modules/03-post-training-and-rl.md))
- **KV cache**: Stored attention keys and values for earlier tokens, reused to speed up generation. ([01](../modules/01-what-is-an-llm.md), [06](../modules/06-open-vs-closed-weights.md))

## L

- **Model Context Protocol (MCP)**: An open standard (Anthropic, 2024) for connecting tools and data sources to models. ([01](../modules/01-what-is-an-llm.md))
- **Model ID / snapshot**: The exact string you send to an API to pick a model. ([05](../modules/05-model-landscape.md))
- **Model picker**: The UI control that lets users choose which model answers in a chat app. ([17](../modules/17-keeping-up.md))
- **Model routing**: Sending easy work to cheaper models and hard work to more capable ones. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **Model snapshot (pinned version)**: A dated, fixed model version offered by an API, as opposed to an alias that moves. ([17](../modules/17-keeping-up.md))
- **Multi-agent debate**: Agents argue over answers for several rounds before converging. ([12](../modules/12-multi-agent-systems.md))
- **Multi-agent system**: Several model instances, each with its own context and role, coordinated by code or by another agent. ([12](../modules/12-multi-agent-systems.md))
- **Multi-head attention**: Running several attention operations in parallel so the model can track different relationships at once. ([01](../modules/01-what-is-an-llm.md))
- **Multimodal model**: A model that handles more than text, such as images or audio. ([01](../modules/01-what-is-an-llm.md))

- **Mythos-class**: Anthropic's tier above Opus, previewed to vetted partners in April 2026 (Project Glasswing) and released in June 2026 as Fable (general) and Mythos (vetted access). ([05](../modules/05-model-landscape.md))

## N

## O

- **Output tokens**: Everything the model generates on a call, including reasoning tokens. ([15](../modules/15-costs-subscriptions-and-apis.md))

## P

- **Time horizon (50%)**: The human-time length of tasks a model completes half the time (METR's measure). ([07](../modules/07-judging-models.md))
- **Token**: A chunk of text (often part of a word) that a model reads and writes; the unit of cost and context limits. ([01](../modules/01-what-is-an-llm.md), [15](../modules/15-costs-subscriptions-and-apis.md))
- **Tokenizer**: The component that splits text into tokens and maps them to integer IDs. ([01](../modules/01-what-is-an-llm.md), [15](../modules/15-costs-subscriptions-and-apis.md))
- **Tool / tool call**: A function a harness exposes to the model with a name, description and input schema; a tool call is the model's structured request to run one. ([08](../modules/08-harnesses-and-tools.md))
- **Tool poisoning**: Hiding instructions in an MCP tool's description, which the model reads but users usually don't. ([14](../modules/14-security-and-prompt-injection.md))
- **Tool search**: Loading tool definitions on demand instead of all at once. ([08](../modules/08-harnesses-and-tools.md))
- **Tool use / function calling**: A model emitting structured requests that a harness executes, with results returned to the context. ([01](../modules/01-what-is-an-llm.md))
- **Top-p (nucleus) sampling**: Sampling only from the smallest set of tokens whose probabilities sum to p. ([01](../modules/01-what-is-an-llm.md))
- **Total vs active parameters**: In MoE, all parameters stored versus those used for a given token. ([01](../modules/01-what-is-an-llm.md))
- **Toxic agent flow**: Invariant Labs' term for a sequence of individually allowed tool calls that, triggered by injected text, adds up to a harmful outcome. ([14](../modules/14-security-and-prompt-injection.md))
- **Training cutoff**: The date after which a model has no training data. ([01](../modules/01-what-is-an-llm.md))
- **Training vs inference**: Training adjusts weights; inference uses frozen weights to produce output. ([01](../modules/01-what-is-an-llm.md))
- **Trajectory (rollout)**: One full sequence of states and actions; for an LLM, a whole answer or agent session. ([03](../modules/03-post-training-and-rl.md))
- **Transformer**: The neural network architecture from "Attention Is All You Need" (2017) that underlies nearly all LLMs. ([01](../modules/01-what-is-an-llm.md))
- **Two-week rule**: Waiting about two weeks after a release before adopting it, unless it solves a current problem. ([17](../modules/17-keeping-up.md))

## U

- **Unified memory**: Memory shared by CPU and GPU on Apple silicon, so large models can load without a discrete GPU. ([06](../modules/06-open-vs-closed-weights.md))
- **Usage cap**: The limit on how much a subscription allows in a rolling window (often 5 hours) or per week. ([15](../modules/15-costs-subscriptions-and-apis.md))
- **Usage limits (quotas)**: Caps on how much a subscription plan can use in a time window (for example, five-hour and weekly limits). ([17](../modules/17-keeping-up.md))

## V

- **Value function (critic)**: A learned network that predicts expected reward, used as PPO's baseline. ([03](../modules/03-post-training-and-rl.md))
- **Verification step**: Checking a finding against the code, ideally by reproducing it with a test, before acting. ([13](../modules/13-ai-code-review.md))
- **Verification tax**: DORA's term for time saved on generation being spent again on checking the output. ([11](../modules/11-verification.md))
- **Verifier**: A test, tool or separate model that checks an agent's claimed result. ([11](../modules/11-verification.md))
- **Verifier's rule**: Jason Wei's claim that the ease of training AI to solve a task is proportional to how verifiable the task is. ([11](../modules/11-verification.md))
- **Vibe coding**: Karpathy's term for building software by prompting an AI and accepting its output without reading the code. ([00](../modules/00-orientation.md))
- **Vibe engineering / agentic engineering**: The disciplined counterpart: AI does most of the typing, a human stays accountable for design, review, and testing. ([00](../modules/00-orientation.md))
- **Vibes**: Experienced users' informal impressions of a model; useful but noisy data. ([07](../modules/07-judging-models.md))
- **Vibes log**: A dated record of notable model successes and failures, used to make informal impressions countable. ([17](../modules/17-keeping-up.md))
- **Vouching**: Ghostty's system in which a maintainer approves a first-time contributor before their PRs are accepted. ([16](../modules/16-open-source-ecosystem.md))
- **VRAM**: A discrete GPU's own memory. ([06](../modules/06-open-vs-closed-weights.md))

## W

- **Warm backup**: A second tool kept configured and in occasional use, so you can switch quickly. ([17](../modules/17-keeping-up.md))
- **Weight-space programming**: A model reading and editing another neural network's weights directly, as numbers, without gradient-based training. ([03](../modules/03-post-training-and-rl.md))
- **Weights (parameters)**: The learned numbers that define a model's behavior. ([06](../modules/06-open-vs-closed-weights.md))
- **Workflow (vs. agent)**: An LLM system following predefined code paths, as opposed to one that directs its own process. ([09](../modules/09-context-engineering.md), [12](../modules/12-multi-agent-systems.md))
- **Workslop**: AI-generated work that looks complete but lacks substance, shifting effort to whoever receives it. ([18](../modules/18-learning-careers-and-responsibility.md))
- **Write / select / compress / isolate**: LangChain's four categories of context-engineering technique. ([09](../modules/09-context-engineering.md))

## Y

- **YOLO / skip-permissions mode**: An agent setting that runs every action without asking for approval. ([14](../modules/14-security-and-prompt-injection.md))
- **YOLO mode**: Running an agent with permission prompts turned off. ([10](../modules/10-agentic-workflows.md))

## Z

- **Zero data retention (ZDR)**: A contractual arrangement in which the provider does not store prompts or outputs after processing. ([15](../modules/15-costs-subscriptions-and-apis.md))
