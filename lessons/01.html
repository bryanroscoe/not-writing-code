The title as GPT-4o's tokenizer splits it: six tokens, with "LLM" cut in two.

This lesson explains what a large language model does with the text you give it. By the end you will know why these models are good at code, why they make things up, and which working habits follow from that.

The colored chips on screen are the lesson title cut into tokens, the units a model reads. More on those shortly.

The one idea

An LLM guesses what comes next

Your phone keyboard suggests the next word because it has seen a lot of text. An LLM does the same job at enormous scale, with far more context.

It reads everything so far and gives every possible next token (a chunk of text) a probability.

Chat and coding agents use this same prediction step.

The one idea

It writes one token at a time, in a loop

A sampler picks one token from those probabilities and appends it to the text. Then the whole thing runs again on the longer text.

This is called autoregressive generation: each output becomes part of the next input.

The one idea

The model learns by predicting the next token

To predict the next token across trillions of tokens of web pages, books, papers and code, a network has to absorb grammar, facts, style and programming idioms.

Predicting the last line of a mystery novel rewards having tracked the plot.

Go deeper: the one idea

The whole novel so far

…and the murderer was   ?  

To fill in the blank, the model has to have tracked the plot.

Training uses the same task. Take real text, hide what comes next, and have the network guess. When the guess is poor, the network's numbers get adjusted. Repeat that across trillions of tokens of text and code.

Guessing well takes more than grammar. To fill the blank after "the murderer was", you need to have followed the whole plot. Nobody told the network to track plots. Tracking them made its guesses better. The same pressure teaches it programming idioms.

One caution. Material that appears often in training comes back reliably. Rare details can come back distorted or invented.

Ask what a network would have to know to predict the next line of a code review comment.

The one idea

Chatting with a model never changes its weights

The weights, also called parameters, are the numbers inside the network. Training adjusts them. Inference uses them as they are to generate text.

When you chat with a model you're running inference, so nothing you type changes its weights.

Tokens and tokenization

The model sees chunks of characters called tokens

A tokenizer splits text into frequent chunks and maps each one to an integer ID. Common words become one token and rare words split into pieces.

OpenAI's rule of thumb is about four characters of English per token. Prices and limits are counted in tokens.

Embeddings

Each token becomes a point in space

Each token ID turns into a list of thousands of numbers called an embedding. Think of them as coordinates.

Training places tokens with related meanings near each other. Each transformer layer then moves a token's point based on the other words it can see.

Go deeper: embeddings

king − man + woman lands near queen. In a transformer, "bank" ends up in different places in "river bank" and "savings bank" once the layers have read the word before it.

Illustrative 2D sketch

An integer ID carries no meaning. So the model first swaps each ID for a long list of numbers, thousands of them, called an embedding. Treat that list as the coordinates of a point.

Training moves the points so that related tokens sit close together. The left sketch is the classic result from 2013. The step from "man" to "woman" roughly matches the step from "king" to "queen".

The right sketch shows what the transformer layers add. "Bank" starts as one point. After the layers read the word before it, the point moves. It lands near "river" in one phrase and near "savings" in the other.

The sketch is a cartoon. The real space has thousands of dimensions, and nobody can draw that.

The transformer

The transformer made training parallel

Nearly every LLM is built on the transformer, from the 2017 Google paper "Attention Is All You Need".

Earlier recurrent networks (RNNs) read words one after another. A transformer processes every position of a training sequence at once, so training can spread across many GPUs.

The top half of the screen shows what came before. A recurrent network reads one word, then the next. Each step waits for the one before it, so the steps inside one sequence cannot run at the same time.

The bottom half is the transformer. During training, all six positions go through the layer in a single step. That made it practical to train on huge amounts of text with huge numbers of GPUs. Today's large models needed that scale.

Clear up one confusion. The parallel part is training. Generation is still one token at a time.

The transformer

Attention lets each token pull from the others

A token's query describes what it's looking for. Its key describes what it offers, and its value holds the information it can pass along.

A token compares its query with the keys, then takes a blend of the values, weighted by the match.

Go deeper: the transformer and attention

Drawn for a model that reads in both directions. A GPT-style model can't look ahead from "it" to "tired". The next screen shows why.

Changing "tired" to "wide" makes "it" more likely to refer to the street.

Illustrative

Attention is how a token gets information from other tokens. Each token has a query, a key and a value. Its query describes what information that token needs. Its key describes what the token is about. Its value holds the information it can pass to another token.

Take the word "it" in the top sentence. Its query is compared with every key. The thick arrow from "animal" means a strong match, so "it" takes most of its blend from "animal". Swap "tired" for "wide" and the thick arrow moves to "street".

Nobody writes these rules by hand. Training learns them. Each layer runs many of these lookups side by side, and the layers are stacked dozens deep. The arrow weights on screen show the idea. They were not measured.

Ask which word "it" refers to and which word told them. Then swap "tired" for "wide" and ask again.

The transformer

GPT-style models can only look back

In the models you'll use for chat and code, a token can attend to its own position and earlier ones. Later ones are hidden from it.

That rule is called the causal mask. It keeps the model from peeking at the tokens it's being trained to predict.

Go deeper: the transformer and attention

Each row is a token doing the looking. Each column is a token it might look at.

can attendmasked: future positions get zero weight
Simplified: one word per token

The previous example let the token "it" use the later word "tired". The models you use for chat and code cannot do that. Each token can look at itself and at earlier tokens only.

Read the grid row by row. The highlighted row is "cross". Its filled squares are "The", "animal", "didn't" and "cross". The two hatched squares are the words that come later, and they are hidden.

This rule is called the causal mask. The model is trained to predict the next token. If it could see that token, there would be nothing to predict.

Ask the room: in "because it was too tired", can the "it" position in a GPT-style model see "tired"? Answer: no. "Tired" comes later, so the mask hides it. Later positions can look back at both words and combine the clues.

Context windows

Weights are long-term memory, context is working memory

The context window is everything the model can see at once: system prompt, conversation, pasted files, tool outputs, its own thinking.

Put the facts it needs in the context, since it can only use what's there and what it learned during training.

A model has two places to get information. The weights hold what it learned in training. That memory is broad and fuzzy, and it stops at the training cutoff date. The context window holds what is in front of it now. That covers the system prompt, the conversation, pasted files and tool results.

The context is precise and current, but it is gone when the session ends. Memory features and files such as CLAUDE.md save notes and put them back into your context next time.

GPT-3 had 2,048 tokens. Frontier models now take up to about a million. Put the facts your task needs into the context.

Watch for "a bigger window is always better." Models often use material buried in the middle of a long context less well than material at the start or end.

Post-training

Post-training turns the raw predictor into an assistant

Straight out of pretraining you get a base model, and a base model continues documents. Ask it a quiz question and it may write more quiz questions.

Post-training teaches it to answer, using examples of good responses and feedback from humans and AIs.

Reasoning models

Thinking is extra tokens the model writes first

A reasoning model is still a next-token predictor. Before the visible answer it writes thinking tokens into its own context and reads them back, so it can work in steps, check itself and change course.

Each token written is one more pass through the network, so more thinking means more computation on your problem. On an API you are billed for every thinking token, whether or not you get to see it.

Compare the two panels. Both are asked whether 3,599 is prime. On the left, the model answers straight away, so the first token of its reply is yes or no. It has read the whole question. But choosing that token is one trip around the loop: one run through a fixed stack of layers. Once the token is picked, it stays.

On the right, the model writes its working first. It tries 7, then 11. Then it spots a shortcut. 3,600 is 60 squared, and the number in the question is one less than that. So its factors are 60 minus 1 and 60 plus 1, which are 59 and 61. Each of those tokens was one more trip around the loop.

The big hosted models do not hand over their raw thinking. You get a summary or nothing. On an API you are billed for every thinking token anyway. On a subscription it counts against your limit.

Ask the room to answer "is 3,599 prime" instantly, then give them thirty seconds with paper. The paper is the thinking tokens. Watch for the idea that thinking is a separate engine inside the model. It is the same network run more times.

Reasoning models

Reasoning models are trained to think first

Nobody writes the thinking by hand. OpenAI's o1, previewed in September 2024, was trained with reinforcement learning to write a long private chain of thought before answering.

Reasoning models

Thinking effort is a dial you set

Many reasoning models decide for themselves how long to think. Often you also get an effort or budget setting to control it.

More thinking means more tokens, which cost money and time. It helps on debugging and design, and it's wasted on boilerplate.

Sampling and temperature

The same prompt can give different answers

The sampler picks from the probabilities, and temperature sets how random the pick is. Temperature 0 always takes the top token, which should be deterministic.

Hosted models often vary anyway, partly because servers batch your request with other people's, so ask important questions more than once.

Tool use

Tools let the model run code and read your files

On its own a model can do neither, and it can't guarantee exact math.

With tool use it emits a structured request, the harness around it runs the tool, and the result goes into the context. An agent repeats that loop until the task is done.

What an LLM is not

Four things an LLM isn't

Most beginner mistakes come from expecting the model to work like a database, search engine, calculator or person. Each habit below corrects one of those expectations.

Go deeper: what an LLM is not

A database

Facts are smeared across billions of weights. No lookup, no record of where a fact came from.

Give it the source material in its context.

A search engine

No live index. Its knowledge stops at a training cutoff date.

Check whether search is on. Ask for links and open them yourself.

A calculator

It sees numbers as tokens and approximates arithmetic.

Have it write and run code.

A person

No memory between sessions unless a product re-inserts notes. No stake in outcomes.

You're responsible for how you use the output, so verify its claims.

Most early mistakes with these models come from treating them like a database, a search engine, a calculator or a person.

If you need information from a particular source, put that source in the context. For current information, check that search is on and open the links yourself. Have the model write and run code for exact arithmetic. You are accountable for what ships, so verify the output first.

Ask which of the four has already caused someone in the room a real problem.

Hallucination

A hallucination is confident output that's false

Training rewards plausible text. When the model lacks a fact, a plausible guess still gets high probability.

In code that looks like invented APIs, nonexistent package names, and descriptions of files it never opened. Give it the real docs and run what it writes.

The model was rewarded for plausible text. When it lacks a fact, a plausible guess still gets high probability. Most benchmarks also score "I don't know" the same as a wrong answer. A guess can only help the score, so models chosen on those scores learn to guess.

In code, watch for invented functions, package names that do not exist, and summaries of files the model never opened. The defenses are listed under the chat. Give it the real docs, let it run the code, and keep your tests and your own review in place.

Ask the room: why would a model invent a function instead of saying "I don't know"? Answer: training rewards plausible text, and most benchmarks score "I don't know" the same as a wrong answer, so guessing scores better than admitting uncertainty.

Sycophancy

It leans toward agreeing with you

Sycophancy is telling you what you want to hear: agreeing with a wrong diagnosis, praising weak code, caving when you push back on a correct answer.

It comes partly from training on human ratings, which favor agreeable answers. Ask for critique instead of approval.

What to remember

Three things to keep

  • An LLM predicts the next token, over and over.
  • Its output is plausible text. It can be confidently wrong and tends to agree with you.
  • Put facts in its context, check its work with tools and tests, and expect different answers each run.

Go deeper: a working mental model

Keep three things from this lesson. First, a language model predicts the next token, again and again.

Second, what it produces is plausible text. Plausible is often correct. It can also be wrong with full confidence, and it tends to side with you.

Third, put the facts the model needs into its context. Check its work with tools and tests. Expect a different answer on a different run.
